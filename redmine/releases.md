## 版本管理规则

### 分支策略

```
main ─────●─────────●─────────●─────────●
           │         │         │         │
           ▼         ▼         ▼         ▼
         v1.0.0   v1.1.0   v1.2.0   v2.0.0
           
develop ──●────●────●────●────●────●───
           │    │    │
           ▼    ▼    ▼
      feature branches
```

### 发布流程

1. 功能开发在 `feature/*` 分支
2. 合并到 `develop` 进行集成测试
3. 版本发布时创建 `release/vX.Y.Z` 分支
4. 测试通过后合并到 `main` 并打 Tag
5. `main` 分支自动部署到生产环境

### 回滚策略

- 数据库 Migration 必须有回滚脚本
- 每次部署保留上一个版本的 Docker Image
- 回滚决策：Blocker 级 Bug → 立即回滚；Critical 级 → 评估后决定
